# BMP280 I2C Clock 400→100 kHz Implementation Plan

## Overview

Change the I2C bus clock from 400 kHz (fast mode) to 100 kHz (standard mode) to accommodate the missing external pull-up resistor on SDA (GP6). The internal ~65 kΩ pull-up is within the 1000 ns rise-time budget at 100 kHz but exceeds the 300 ns budget at 400 kHz, causing BMP280 detection to fail.

## Current State Analysis

- `src/pressure_sensor.c:29`: `i2c_init(i2c1, 400000)` — only place bus speed is set
- GP6 (SDA): internal pull-up only (~50–80 kΩ)
- GP7 (SCL): internal pull-up + external 4.7 kΩ
- BMP280 SDO pulled high → address 0x77
- `/api/status` currently reports sensor = `"None"` because `bmp280_detect()` fails

## Desired End State

`/api/status` reports `"sensor":"BMP280"`. The 50 Hz async pressure FIFO starts successfully.

### Key Discoveries
- `src/pressure_sensor.c:29` — single literal controls bus speed for both BMP280 and MS5607 drivers
- `src/bmp280_driver.c:65-88` — detection probes 0x76 then 0x77; both use `i2c_write_blocking` (no timeout)
- No other code sets or reads the I2C clock rate

## What We're NOT Doing

- Adding an external pull-up resistor (hardware change deferred)
- Making the clock rate configurable at runtime
- Changing the 50 Hz sample rate or any sensor compensation logic

## Implementation

### Phase 1: Change I2C clock rate

**File**: `src/pressure_sensor.c`  
**Line 29** — change `400000` → `100000`:

```c
// Before
i2c_init(i2c1, 400000);

// After
i2c_init(i2c1, 100000);
```

That is the only required code change.

### Phase 2: Version bump

Bump `VERSION` to `2.1.49` to mark this fix.

### Phase 3: Build and flash

```bash
cd build && make -j$(nproc) pyro_fw
```

Flash via bootsel or OTA.
